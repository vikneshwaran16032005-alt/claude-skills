# The module template: the five-part shape

Every module follows the same five parts. This predictability is a feature, not
monotony: a beginner always knows where they are, and knows a drill and a checkpoint are
coming so they read actively instead of passively.

Point every drafting agent at this file AND at the user's approved template module (the
first one you built and they signed off on) as the concrete exemplar to match.

## The shape

Use `##` for the module title (so it starts a fresh page when rendered), and `###` for
each of the five parts.

```
## Module N: [Plain-English title, no jargon]

### 1. What this is, and why it matters
2-5 short lines. What the module gives them, and why it matters to whether they
succeed. Hook the beginner. No theory yet.

### 2. How it works
The actual teaching, from zero. This is the biggest part. Every insider term explained
or renamed on first use. Lots of plain analogies from ordinary life. Short paragraphs.
Build one idea at a time; never assume the previous line landed unless you made it land.

### 3. Watch it happen
Drop into the ONE running worked example and show the thing actually happening: a real
snippet of dialogue, a real artifact, a walked-through scenario. This is where the
abstract craft becomes concrete. Show it done right; optionally show a beginner doing it
wrong for contrast.

### 4. Your drills
Concrete things the reader DOES before moving on, ideally in pairs or solo reps. Not
"think about" ... actual reps: "record yourself saying X ten times," "run this scenario
with a partner playing Y." Drills are how a course makes someone able, not just informed.

### 5. Checkpoint
How they know they're ready for the next module. A clear, honest bar: "you're ready when
you can do X without the page." If they can't, tell them to re-drill this module, not
push on. This protects the no-blindspots promise.
```

## The exemplar

The canonical, user-approved example of this shape at the right depth and voice is the
first module set you build and get signed off. For the sales course it is:
`/Users/vik/Project 7/course/Module_1-2_Foundation.md`

Read it before drafting any module. Match its depth (thorough, ground-zero handholding),
its voice (the user's, full casual), its short-paragraph rhythm, and this five-part shape
exactly. When in doubt about "how deep" or "how casual," that file is the answer.

## Depth calibration

At full handholding depth, a single module runs roughly 3,000-5,000 words; modules with
more moving parts (discovery, objections, closing, the end-to-end worked example) run
heavier and that is fine. Thorough beats short, always. A book-length course (50k+ words)
is the expected, correct outcome, not a sign of bloat.
